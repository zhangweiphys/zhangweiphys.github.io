Git 日常开发常用命令速查表

以下按从克隆仓库 → 本地开发 → 提交同步的完整流程整理，覆盖日常高频使用场景，可直接复制留存。

一、仓库初始化与克隆

命令 含义 应用场合
git clone <远程仓库地址> 将远程仓库完整下载到本地，自动关联远端并命名为 origin 第一次拿到项目、从 Gitee/GitHub 拉取代码到本地
git init 在当前文件夹初始化一个全新的本地 Git 仓库 本地从零新建项目，后续再关联远程仓库

二、远程仓库管理

命令 含义 应用场合
git remote -v 查看当前仓库关联的所有远程仓库地址（拉取/推送地址） 确认项目绑定的是哪个远端仓库
git remote show origin 联网查询远程仓库详细信息：默认分支、分支追踪关系、实时同步状态 不执行 fetch 也能实时检查远端是否有更新
git remote add origin <远程地址> 给本地仓库添加远程仓库，别名设为 origin 本地 git init 新建项目后，绑定 Gitee/GitHub 远端

三、查看状态与代码差异

命令 含义 应用场合
git status 查看当前分支状态、工作区修改、暂存区状态、与远程分支的同步情况 开发中随时查看：改了哪些文件、有没有未提交内容、本地是否落后远程
git diff 对比「工作区 ↔ 暂存区」的代码差异 查看自己改了哪些内容，还没执行 git add
git diff <本地分支> origin/<远程分支>
例：git diff master origin/master		 对比「本地分支 ↔ 远程分支」的代码差异 git fetch 之后，查看远程具体改了哪些文件、哪几行

注意：git status 默认只对比本地缓存的远程快照，不会自动联网。想获得最新远程状态，需先执行 git fetch origin 刷新缓存。

四、暂存与提交（本地版本保存）

命令 含义 应用场合
git add <文件名> 将指定文件的改动加入暂存区 只提交部分文件，或逐个确认要提交的修改
git add . 将当前目录下所有改动文件批量加入暂存区 改动文件多，确认全部要提交时使用
git commit -m "提交说明文字" 将暂存区的内容正式提交到本地仓库，生成一个版本记录 完成一个功能 / 修复一个 bug，保存一个可回溯的版本
git commit -am "提交说明文字" 一步完成「暂存 + 提交」，仅对已被 Git 跟踪过的文件生效 快速提交已有文件的修改，省掉单独 add 的步骤

五、同步远程仓库

命令 含义 应用场合
git fetch origin 从远程拉取所有新提交、新分支到本地 .git 数据库；只下载，不修改工作区代码 安全查看远程更新，先看改了什么，再决定要不要合并；无任何风险
git pull 等价于 git fetch + git merge，拉取远程更新并自动合并到当前本地分支 确认远程更新无误后，一键同步到本地代码
git push origin <分支名>
例：git push origin master		 将本地的提交推送到远程仓库对应分支 本地提交完成后，把代码同步到 Gitee/GitHub 远端

补充：git fetch 无任何输出 = 远程没有新更新，本地已是最新状态。

六、分支操作

命令 含义 应用场合
git branch 列出所有本地分支，标 * 的是当前分支 查看当前在哪个分支、有哪些本地分支
git branch <分支名> 新建一个分支 基于当前版本开新分支做开发
git switch <分支名>
或 git checkout <分支名>		 切换到指定分支 在不同功能分支之间切换
git switch -c <分支名>
或 git checkout -b <分支名>		 新建分支并立即切换过去 最常用：开新分支同时切过去开始开发
git merge <分支名> 将指定分支的代码合并到当前分支 功能开发完，把特性分支合并回主分支
git branch -d <分支名> 删除本地分支 功能合并完成后，清理无用的旧分支

七、查看提交历史

命令 含义 应用场合
git log 查看完整提交历史（哈希、作者、时间、提交说明） 回溯版本历史，查看过往提交记录
git log --oneline 精简版提交历史，一行显示一个提交 快速浏览提交脉络，方便找版本号
git log master..origin/master 查看「远程有、但本地没有」的提交 fetch 后，查看远程新增了哪几次提交
git log origin/master..master 查看「本地有、但远程没有」的提交 检查自己有哪些提交还没 push

分页浏览时，按 q 退出，按空格翻页，按方向键逐行滚动。

八、撤销与回退

命令 含义 应用场合
git restore <文件名> 丢弃工作区的修改，文件还原到上一次提交的状态 改坏了文件，想撤回所有修改，恢复原样
git restore --staged <文件名> 取消暂存，文件从暂存区退回工作区 git add 加错了文件，撤回来
git reset --soft HEAD~1 撤销最近 1 次提交，改动保留在暂存区 提交说明写错了、或想重新整理提交内容
git reset --hard HEAD~1 撤销最近 1 次提交，所有改动彻底删除 确认丢弃最近一次提交的全部内容，慎用

九、临时储藏（Stash）

命令 含义 应用场合
git stash 把当前未提交的改动临时藏起来，工作区恢复干净 有未提交的修改，但需要先 pull 代码 / 切换分支，又不想提交半成品
git stash pop 取出最近一次储藏的改动，应用回当前工作区 处理完其他事情后，恢复自己之前的修改继续开发
git stash list 查看所有储藏记录 忘记藏了几次，查看列表
