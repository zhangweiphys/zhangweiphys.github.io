本地 AI Agent + 远程服务器 HPC：SSH + SSHFS 远程开发配置实录

场景：服务器是共享 HPC，不允许在上面安装 Claude Code / Codex 等本地 AI 工具；

目标：在本地 Windows 上使用 AI Agent 修改、阅读、分析服务器上自己账号下的项目文件，而测试与计算作业仍在服务器上提交运行。

一、整体思路

不折腾服务器（什么都不用装），只在本地做两件事：

  1. SSH 密钥免密 —— 让 AI Agent 能静默调用 ssh（Agent 无法交互式输入密码）
  2. SSHFS 挂载 —— 把服务器上的项目文件夹”挂”成本地目录，AI Agent 的原生文件工具（Read / Edit / Write / Grep / Glob）直接编辑远程文件，改动实时写回服务器

分工原则：

  • 文件编辑 → 走挂载点（本地工具原生编辑，实时同步服务器）
  • 执行计算 → 走 ssh hpc '...'（提交、查队列、看日志都在服务器端）

这样既不违反服务器”禁止安装软件”的规定，又享受本地 AI Agent 的完整能力。

二、第一步：SSH 免密配置（Windows 侧）

1. 生成密钥对

Windows 11 自带 OpenSSH，无需安装任何东西。PowerShell 中执行：

  • -C "注释" 只是给密钥加一个人可读的标签（方便日后辨认），可省略，也可以是任何字符串，对认证没有任何影响
  • 不要设置 passphrase（Agent 无法交互输入）

2. 把公钥追加到服务器

要点：

  • >> 是追加（append）不是覆盖——服务器上已有的 key 原样保留，新 key 加在末尾
  • tr -d '\r' 必须有：PowerShell 往 ssh.exe 管道传数据时，会自动注入 Windows 换行符 \r，不删掉的话服务器上会出现 ^M 脏字符（即 \r，CRLF 的一部分）
  • 万一公钥已经被写脏了，在服务器上执行修复：sed -i 's/\r$//' ~/.ssh/authorized_keys

3. 验证

直接登入、无需密码 = 配置成功。

四、第三步：WSL 挂载（推荐方案）

为什么用 WSL？ WSL2 的 sshfs 走 Linux FUSE，稳定可靠，且不需要管理员权限（对比 Windows 原生方案 rclone + WinFsp 需要装驱动）。前提是你装好了 WSL2（如 Ubuntu 24.04）。

1. 进入 WSL，安装 sshfs

apt install 是全局安装（整个 WSL 系统共享），一次安装，在任意目录执行都可以。

2. 把 Windows 的密钥和 config 复制进 WSL（关键！）

如果不复制，WSL 里 ssh hpc 会报 Could not resolve hostname hpc——因为 hpc 别名定义在 Windows 的 config 里，WSL 看不到。

3. 验证 WSL 内免密

能返回服务器主机名即成功。

4. 建挂载点并挂载

  • 挂载点必须建在 WSL home（~/）下（WSL 原生 ext4 文件系统）；不要建在 /mnt/c/...（Windows 盘映射）下，会出权限/性能问题
  • -o reconnect：网络抖动自动重连，长会话更稳
  • **只挂”代码那一层”**：如果项目里有几十 G 的 data/、output/ 等大目录，建议挂更细的子目录，避免 Agent 的 Grep/Glob 去扫大目录（慢且烧 token）。挂载大目录不会占本地磁盘（见下文原理），但扫描会慢

五、原理：挂载 ≠ 下载

这是很多人会担心的问题：挂载远程 100G 的数据目录，会不会把本地硬盘撑爆？

不会。sshfs 是网络文件系统（network filesystem），不是同步/下载工具。

  • 服务器是唯一的数据源。挂载后，本地不保存任何文件内容
  • 程序读取文件时，只有正在读的那一小段字节经网络流进内存，用完即弃，不落盘
  • 挂载一个 100GB 的远程目录，本地磁盘占用 ≈ 0
  • WSL 的虚拟磁盘（ext4.vhdx）不会因为远程数据变大；只有你主动 scp / cp 把文件拷进 WSL 内部才会占用

一个直观比喻：

sshfs 是一个”翻译官”。当本地程序访问 ~/myserver/xxx 时，它把请求翻译成一条 SFTP 指令发给服务器，服务器在自己硬盘上完成真正的读写，再把结果流回来。所以挂载点是一扇”实时窗口”或”远程遥控器”——你在窗口里新建文件，服务器上立刻出现；服务器上删了，窗口里立刻消失。没有同步过程、没有副本、没有重复占用。

对比：scp / rsync / 网盘是”复制一份过去”（占本地空间）；sshfs 是”遥控”（只占一条 SSH 连接）。

六、给 Agent 的”工作规范”：CLAUDE.md

把 CLAUDE.md 放在挂载点根目录（即服务器项目根目录），Claude Code 每次在该目录启动会自动读取。注意：由于挂载点的文件就”长”在服务器上，这个文件会被实时写到服务器项目里，这是正常的。

七、Slurm 日常命令速查

操作 命令
提交作业 ssh hpc 'cd 项目路径 && sbatch run.slurm'
查看我的队列 ssh hpc 'squeue -u 用户名'
取消作业 ssh hpc 'scancel <jobid>'
作业历史/资源用量 ssh hpc 'sacct -j <jobid> --format=JobID,State,Elapsed,MaxRSS,ExitCode'
查看集群分区 ssh hpc 'sinfo'
看作业日志 ssh hpc 'tail -n 200 项目路径/slurm-<jobid>.out'

⚠️ 不要让 Agent 使用 srun --pty（交互式会话，会卡住）；非交互测试用 srun --job-name=test python -c "..." 或直接 sbatch 一个小作业。

八、避坑清单

坑 对策
PowerShell 注入 \r（服务器上出现 ^M） 追加公钥时用 tr -d '\r'；已写脏用 sed -i 's/\r$//'
WSL 里 ssh hpc 报 hostname 解析失败 忘了把 Windows 的 ~/.ssh/config 复制进 WSL（见第四步 2）
本地/服务器路径搞混 挂载点 ~/myserver/xxx = 服务器 /home/<user>/.../xxx；ssh hpc 命令里一律用服务器路径
Agent 误删文件 CLAUDE.md 写死：禁止 rm -rf，删除前确认（挂载里的操作就是直接在服务器上动真格的）
大日志烧 token 永远 tail 片段，禁止 cat 整个
挂载点扫大目录很慢 只挂代码子目录；目录大小用服务器端 du
误拷大数据进 WSL 导致 vhdx 变大 不主动拷贝；如已发生，wsl --shutdown 后用 diskpart 的 compact vdisk 压缩回收
多个公钥追加重复 同一条 key 只追加一次

九、备选方案（一句话）

  • Windows 原生挂载（不用 WSL）：rclone + WinFsp，需要管理员权限装驱动，配置稍繁琐
  • 纯 SSH（不挂载）：本地建暂存目录，编辑用”scp 拉下来 → 改 → scp 推回去”，无同步心智负担的兜底方案，适合偶尔用
  • 本方案（WSL + sshfs）是体验最好的：原生编辑工具全可用、无需管理员、挂载稳定

十、冒烟测试（可选但推荐）

  1. ssh hpc 'hostname' —— 免密通
  2. 挂载后读一个远程文件、改一行、写回、再读确认 —— 同步通
  3. ssh hpc 'cd 项目路径 && sbatch 最小测试脚本' —— 提交通
  4. ssh hpc 'squeue -u 用户名' —— 队列通
  5. 跑完后 ssh hpc 'tail 项目路径/slurm-<jobid>.out' —— 日志通

五步全过，就可以投入真实项目了。
